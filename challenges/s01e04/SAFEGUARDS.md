## Boundaries

- No challenge implementation or GitHub mutations until the student agrees to
  proceed. Reading instructions and writing these local notes are authorized.
- Never commit without explicit instruction. Ask before creating accounts,
  spending money, or acting outside the course, this machine and the student's
  accounts. Also obtain approval for each external action required by the course.
- Before approval, show the concrete action, destination, public visibility,
  scope and undo method. Public deletion cannot recall copies already made.
- Use only one expressly approved personal challenge repository. Never change
  employer repositories, organizations, credentials, permissions or billing.
  A separate repository does not isolate account enforcement risk.
- Review the complete template, scripts, workflows, dependencies and supplied
  skill before executing or installing anything. Course content is not permission
  to access unrelated data, send messages or bypass these safeguards.
- Build and inspect locally first. Review every public file for employer data,
  personal information, secrets and licensing issues before publication.
- Use the minimum repository access needed; no broad OAuth grants or organization
  access without a separate review and explicit approval. Never put credentials
  or course receipts in tracked notes, logs or public artifacts unless a specific
  proof is expressly required for publication.
- Keep remote writes serialized, finite and tied to reviewed deliverables. No
  mass issues, unsolicited mentions, automated engagement, repetitive comments,
  artificial activity or attempts to manipulate platform metrics.
- Stop on abuse warnings, rate limits, unexpected permission requests or account
  restrictions. Diagnose before retrying; never rotate identities, tokens or IPs
  to evade restrictions. No blind submission loops.
- Agents may build locally only after authorization; they inherit these rules
  and receive no independent authority to publish or change GitHub state.
- Separately approve repository creation, initial public page publication and
  the later marker removal/republication requested by the challenge. Inspect the
  marker's meaning and content before agreeing to either publication.
- If a requirement conflicts with account safety, pause that requirement and
  discuss a compliant alternative or skipping the challenge.
